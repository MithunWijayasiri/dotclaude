Overview

Claude Code reads three kinds of file. This repo holds mine.

Plain markdown in ~/.claude — output styles shape how Claude answers, skills add repeatable jobs, and CLAUDE.md sets the defaults. Nothing is a plugin; every file is text you can read and edit.

  • output-styles/

    Replaces how Claude answers. Loads at session start; shapes every reply until you switch. One is here.

  • CLAUDE.md

    Standing instructions. Loads in every session, in every project — engineering defaults, comment style, and what needs approval.

  • skills/

    A repeatable job in ~/.claude/skills/<name>/SKILL.md, loaded on demand when the task matches its description.

The router is mounted at a different path from the one you're requesting.

In server.js:

  app.use('/api/user', usersRouter);

The request goes to /api/users. Express matches a mount path by whole
path segments, so users doesn't match user. The request never
reaches usersRouter, no other route handles it, and Express falls
through to its default 404.

Two ways to fix it:

- Change the mount to /api/users. Plural is the usual convention
  for a collection, and it's a one-line change.
- Change the caller to /api/user, if other clients already depend
  on the singular path.

I'd go with the first unless something else already calls /api/user.

ASD-STE100

Structured output following ASD-STE100 English standards. Named for the controlled English of aircraft maintenance manuals — where a technician must not read a procedure two ways.

  • Every fact, name, number, and path kept
  • One term per meaning, held for the whole answer
  • Max 20 words and one idea per sentence, simple tenses, no -ing forms
  • Everyday words; a technical term explained on first use
  • Active voice, imperative instructions
  • Result first, detail after, then Verified: Updated: Skipped: Remaining: Next:
  • Each label once; two or more items nest under it

Skills

A skill is a task procedure Claude Code loads on demand — one way to do one job.

  • compact-markdown

    Telegraphic markdown for AI-facing docs. Strips filler, keeps code, examples, and concrete detail — compact and still human-readable.

  • humanize

    Remove AI writing patterns from prose. Use for human-facing writing where voice matters.

  • handoff-session

    Hand the whole session to the next one — current state, decisions made, blockers, next steps. Dead ends and resolved detail are dropped.

  • offload-task

    Write one stuck problem into a standalone brief — goal, failing behaviour, repro, and every attempt with what it produced, code and manual checks alike.

  • claude-project-rulesClaude only

    Author .claude/rules/*.md — paths: scoping, lazy-load against always-on, shared rules by symlink, and when a rule beats CLAUDE.md or a skill.

  • html-landing-page

    Design a distinctive static landing page. Plan palette, type, and one signature element before any HTML — and never ship the AI-default look.

  • git-merge

    Merge a branch into yours without losing local unstaged work. Diagnose each conflict, then run the repo's own checks to catch the ones git merged cleanly but wrongly.

  • pr-reviewManual only

    Review a PR, branch, commit, or uncommitted work for defects — bugs first, structure second, style last. The target is resolved explicitly, and a bad ref or an empty diff stops the run rather than being guessed at. Findings come back grouped Blocker / Should fix / Nit, each with file:line, the concrete input that breaks it, and a fix. Invoked manually with /pr-review.

  • zoom-outManual only

    Map an unfamiliar code area before touching it — purpose, flow, callers, boundaries, risks. Nothing is edited and no mutating command runs until the map is done. Invoked manually with /zoom-out.

Both handoff-session and offload-task write a markdown file for a session that was not here — what differs is the payload. handoff-session carries the session: state, decisions, blockers, next steps, so the work continues. offload-task carries one unsolved problem and the dead ends already burned on it, so a fresh session or another agent can take a run at it without repeating them.

compact-markdown also ships references/skill-authoring.md — good practices for writing effective skills, distilled from Claude Code, Codex, and mattpocock/skills.

CLAUDE.md

Standing instructions for every session. Five sections:

  • General

    Never guess; ask one targeted question. Lead with the result, no filler.

  • Engineering

    KISS, YAGNI, fail fast. One recommendation, not a survey.

  • File & Command Safety

    Approval before anything destructive. gh for GitHub, Conventional Commits on request.

  • Comments

    Constraints only, never a restatement of the code.

  • External Docs

    Library questions go to context7, not memory. Setup below.

Procedure

Install

Get the files, then copy the parts you want into ~/.claude/. Nothing to build.

No git? Download the latest release — the ZIP bundles the output styles, skills, CLAUDE.md, README, and license.

Use a .claude/ folder inside a repo instead of ~/.claude/ to scope any of this to that one project. Copying CLAUDE.md replaces whatever sits at the target, so read your own first.

Connect context7

The External Docs section of CLAUDE.md sends library, framework, and CLI questions to context7 instead of letting Claude answer from memory. That is an MCP server, not a file in this repo — copy CLAUDE.md without it and the instruction falls back to a web search. Connect it once, at user scope:

A free key comes from the context7 dashboard. For a local server instead: claude mcp add --scope user context7 -- npx -y @upstash/context7-mcp --api-key YOUR_API_KEY.

Turn on an output style

Copying the file does not select it. Type /config in a session and pick one under Output style. Claude Code saves that choice per project, in .claude/settings.local.json.

To make a style your default everywhere, set the field yourself:

The value is the name: field from the file's frontmatter, not the filename. A style is part of the system prompt, so it takes effect after /clear or in your next session.
